# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this folder.

기온 기반 코디 추천 웹사이트("오늘 뭐 입지?")다. 순수 HTML/CSS/JS 파일 하나로 되어 있고 서버나 외부 라이브러리가 필요 없다.

## 파일과 실행

- `index.html`: 화면, 스타일, 데이터, 추천 로직이 모두 들어 있다. 더블클릭해서 브라우저로 열면 바로 동작한다.
- `코디추천_실행.bat`: 같은 폴더의 `index.html`(`%~dp0`)을 기본 브라우저로 연다. CRLF 줄바꿈 UTF-8(`chcp 65001`)로 저장한다.
- 브라우저로 확인할 때는 이 폴더에서 `python -m http.server 8766 --bind 127.0.0.1`을 띄우고 `http://127.0.0.1:8766/index.html`을 연다. 확인이 끝나면 서버를 끈다. Chrome 확장이 없으면 headless Edge(`msedge --headless --dump-dom` / `--screenshot`)로 확인할 수 있다.

## 배포 (휴대폰에서 열기)

- Netlify Drop(app.netlify.com/drop)에 `배포용/` 폴더를 끌어다 놓아 공개 https 주소로 올린다. https여야 휴대폰에서 '내 위치로'(위치 권한)가 동작한다.
- `배포용/index.html`은 `index.html`의 복사본이다. `index.html`을 고친 뒤에는 `배포용/`에 다시 복사하고, Netlify 사이트의 Deploys 화면에 폴더를 다시 끌어다 놓아 갱신한다.
- `CLAUDE.md`와 `.bat`은 공개할 필요가 없으므로 `배포용/`에 넣지 않는다. 업로드(공개)는 사용자가 직접 한다.

## 동작

- 기온: **외부 API를 절대 쓰지 않는다**(사용자 요청, 비용 걱정). `CITIES`에 지역별 기상청 평년값(1991~2020, 월평균 최고·최저 대략값)을 넣어 두고, `normalToday()`가 매달 15일 기준으로 앞뒤 달을 이어 오늘의 평년 최고/최저를 계산한다. 추천 기온은 (최고+최저)/2이고 슬라이더로 직접 맞출 수 있다. 실제 날씨는 기상청 날씨누리 링크로만 연결한다. 기본 지역은 서울, `내 위치로`는 브라우저 위치로 `nearestCity()`가 가장 가까운 지역을 고른다(위치는 밖으로 보내지 않는다). 지역을 추가할 때는 위도·경도와 12개월 최고·최저를 함께 넣는다.
- 검색: `parseQuery()`가 검색어에서 색(`COLORS`의 alias)과 옷(`ITEMS`의 alias)을 가장 긴 별칭 기준으로 찾는다. 상의·아우터를 검색하면 하의를, 하의를 검색하면 상의를 추천한다. 가방만 검색하면 안내 문구를 띄운다.
- 옷 모양: `SHAPES`에 넥라인·소매·핏·기장·허리 단어가 있고, `parseQuery()`가 그룹마다 가장 긴 단어 하나를 고른다. 옷 종류(`cats`)에 맞지 않는 조건은 빼고 화면에 알린다. 옷 종류 없이 모양만 쓰면 기본 옷으로 바꾼다(반팔 → 반팔 티, 와이드 → 와이드 팬츠, 부츠컷 → 청바지 등). 티셔츠는 소매 단어에 따라 반팔/긴팔/민소매로 바뀌고, 다른 상의는 `shapedItem()`이 소매 길이만큼 입기 좋은 기온을 옮긴다(`SLEEVE_TEMP`).
  - 모양 단어와 겹치는 별칭(반팔, 민소매, 와이드, 일자핏)은 `ITEMS` 별칭에 넣지 않는다. 넣으면 "반팔 니트"가 티셔츠로 잡힌다.
  - `silhouetteRule()`: 크롭 상의 → 하이웨이스트·와이드 하의, 오버핏 상의 → 일자·슬림 하의, 와이드·부츠컷 하의 → 크롭 상의, 슬림·짧은 하의 → 오버핏 상의. 상대 옷 이름 앞에 핏 글자(`fitLabel`)를 붙인다. 하의의 `sil`, 상의의 `crop`/`over` 속성을 쓴다.
  - 넥라인별 액세서리: 브이넥 펜던트, 라운드넥 레이어드, 반폴라·터틀넥 롱 목걸이, 카라 시계, 스퀘어넥·오프숄더 초커.
- 추천 점수(`recommend()`): 색 궁합(`partners` 순서) → 기온 적합도(`tempFit`, 범위 밖 3°C 초과면 제외) + 스타일 겹침 + 예시 코디 데이터 가산점(`lookBonus`, 같은 계절 가중치 1). 11°C 이하면 겉옷도 붙인다. 가방은 `pickBag()`/`pickBagColor()`가 스타일과 명도 대비로 고른다.
- 모자·액세서리: `pickHat()`은 기온 범위 안(`tempFit` 3점)이고 스타일이 겹치는 모자만 고르고, 없으면 모자를 추천하지 않는다. `pickAccessories()`는 기온(8°C 이하 머플러, 23°C 이상 선글라스), 스타일(로맨틱 진주 / 오피스·미니멀 시계 / 그 외 목걸이), 따뜻한 색이면 골드·차가운 색이면 실버(`WARM`), 바지면 가죽 벨트 규칙으로 최대 2개를 고른다. 머플러 색은 상하의·겉옷·모자 색과 겹치지 않게 한다.
- 실제 코디 사진: 인스타그램·핀터레스트 내용을 가져오지 않고, `pinterestUrl()`/`instagramUrl()`로 검색 결과 페이지를 새 탭에서 여는 링크만 만든다(검색어 전체 + 추천 조합별).
  - 핀터레스트는 한국어보다 영어 검색 결과가 훨씬 많아서 `englishName()`이 영어 검색어를 만든다(색 → 모양 → 옷 + `outfit`, 예: "light wash wide leg jeans outfit"). `COLORS`·`ITEMS`·`SHAPES`에 항목을 추가할 때는 `en`도 함께 넣는다. 인스타그램은 한국어 해시태그를 그대로 쓴다.
- 사진 분석(외부 API 없음): 사진을 FileReader의 data URL로 읽어 canvas에 그린다(blob URL은 file://에서 canvas가 오염될 수 있어 쓰지 않는다). 사용자가 상의 → 하의 → 가방 순서로 클릭하면 `samplePhoto()`가 클릭 주변 칸의 중간값 색을 읽고, `nearestColor()`가 Lab 거리로 `COLORS` 중 가장 가까운 색을 골라 추가 폼에 채운다. 데님 색은 하의에서만 고른다. 옷 종류와 소재는 사진으로 판별하지 않고 사용자가 고른다.
- 분석: `SAMPLE_LOOKS`(직접 정리한 예시 코디) + 사용자가 추가한 코디(localStorage `userLooks`)를 계절별로 집계한다.

## 디자인

- 핀터레스트 무드보드 콘셉트: 크림·테라코타 톤, 제목은 Google Fonts `Gowun Batang`(오프라인이면 기본 명조로 대체), 둥근 카드(24px)와 부드러운 그림자.
- 색은 모두 `:root` 변수로 정의하고 다크 모드(`prefers-color-scheme`, `data-theme`)도 같은 변수 이름으로 다시 정의한다. 색 점 테두리는 `--sw-border`를 써서 다크 모드에서 검정 점이 묻히지 않게 한다.
- 추천 카드(`.pin`)는 4개뿐이라 `grid`로 가로부터 채운다. 같은 줄 카드는 높이를 맞추고(`align-items: stretch`), '왜 어울릴까?'를 펼치면 이유 목록이 카드 위에 겹쳐 떠서 카드 크기가 변하지 않는다. 분석 카드(`.stats`)만 CSS `columns` 벽돌 배치를 쓴다. 핀 윗부분 배경은 상의·하의 색 그라데이션, 아래 띠는 그 코디의 팔레트다.
- 720px 이하에서는 추천 카드 2열, 420px 이하에서는 분석 카드 1열. headless Edge는 창 너비가 496px보다 작아지지 않으므로 휴대폰 화면은 390px iframe에 넣어 캡처해서 확인한다.

## 데이터 원칙

- 인스타그램·핀터레스트는 약관상 자동 수집(크롤링)이 금지되어 있어 실제 사진을 가져오지 않는다. 화면에도 예시 데이터임을 밝힌다.
- 색을 추가할 때는 `COLORS`에 `name`, `hex`, `alias`, `partners`를 모두 넣는다. 데님 색(`DENIMS`)은 `colors` 목록이나 `denimOk`가 있는 옷에만 쓰인다.
- 화면 글자는 한국어로 쓰고, 조사는 `josa()`/`josaRo()`로 받침에 맞춘다. 휴대폰 화면에서도 보기 좋게 만든다.
